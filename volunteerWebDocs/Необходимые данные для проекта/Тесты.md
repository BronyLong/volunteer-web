# План тестирования

## 1. Цели тестирования

- Проверка соответствия веб-приложения установленным функциональным и нефункциональным требованиям.
- Выявление дефектов в работе клиентской части, серверной части и взаимодействия с базой данных.
- Проверка корректности основных пользовательских сценариев для ролей: гость, волонтёр, координатор и администратор.
- Проверка корректности разграничения прав доступа между ролями пользователей.
- Оценка удобства использования пользовательского интерфейса.
- Проверка стабильности работы приложения при одновременном обращении нескольких пользователей.
- Проверка корректности обработки ошибок и отображения сообщений пользователю.

## 2. Типы тестирования

- **Модульное тестирование серверной и клиентской части приложения**  
    Проверяются отдельные React-компоненты, страницы, вспомогательные функции, API-маршруты Express, middleware авторизации и серверные модули.
- **Функциональное тестирование интерфейса**  
    Проверяются основные функции приложения через пользовательский интерфейс: регистрация, вход, просмотр мероприятий, подача заявок, создание и редактирование мероприятий, работа с профилем, уведомления и административная панель.
- **Тестирование удобства использования**  
    Проверяется, насколько удобно пользователям разных ролей выполнять основные действия: найти мероприятие, подать заявку, создать мероприятие, обработать заявки, изменить профиль, воспользоваться админ-панелью.
- **Нагрузочное тестирование**  
    Проверяется стабильность серверной части при одновременных запросах к основным API: получение списка мероприятий, открытие мероприятия, авторизация, подача заявок, получение профиля и работа с уведомлениями.

## 3. Критерии начала и окончания тестирования

### Критерии начала тестирования

- Реализованы основные модули клиентской и серверной части приложения.
- Подготовлена структура базы данных PostgreSQL.
- Загружены тестовые данные: пользователи, профили, категории, мероприятия, заявки и уведомления.
- Настроено тестовое окружение для запуска frontend и backend.
- Установлены зависимости проекта.
- Подготовлены тестовые учётные записи для ролей: волонтёр, координатор и администратор.
- Настроены инструменты автоматизированного тестирования.

### Критерии окончания тестирования

- Все критические тесты выполнены успешно.
- Все блокирующие дефекты исправлены.
- Основные пользовательские сценарии проходят без ошибок.
- Проверены права доступа для всех ролей пользователей.
- Клиентская и серверная части проходят автоматизированные тесты.
- Интерфейс корректно отображается на основных разрешениях экрана.
- Нагрузочное тестирование не выявило критических сбоев в работе серверной части.
- Результаты тестирования зафиксированы в отчёте.

## 4. Ресурсы

### Инструменты

- **Vitest** — автоматизированное модульное тестирование клиентской и серверной части.
- **React Testing Library** — тестирование React-компонентов и пользовательского поведения.
- **jsdom** — эмуляция браузерного окружения при тестировании React-приложения.
- **Supertest** — тестирование API-маршрутов Express.
- **PostgreSQL** — тестовая база данных приложения.
- **npm scripts** — запуск тестов, покрытия, frontend и backend.
- **DevTools браузера** — ручная проверка интерфейса, адаптивности и сетевых запросов.
- **JMeter** — проведение нагрузочного тестирования API.

### Тестовые данные

- Тестовые пользователи с ролями: волонтёр, координатор, администратор.
- Тестовые профили пользователей.
- Тестовые мероприятия с разными датами, количеством мест, категориями и статусами.
- Тестовые заявки на участие в мероприятиях.
- Тестовые уведомления пользователей.
- Тестовые значения для проверки ошибок: неверный пароль, несуществующее мероприятие, недоступный профиль, отсутствующий токен авторизации, пользователь без нужной роли.
